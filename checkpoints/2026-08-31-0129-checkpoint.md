- Extracted the vendor image's source (`vllm/vllm-openai:glm53-flash`, vLLM

  `ai.vllm.build.pipeline: local` — a **local build**, commit not on any remote,
  so there was no branch to clone.
- **Disproved both fix options in `proxmox/plans/108-vllm-build-handover.md`.**
  (a) the "sm100 sibling that already serves this model" rejects
  `qk_nope_head_dim=256` (GLM-5.3's value); (b) unpacked bf16 dead-ends at
  `TllmGenFmhaRunner: Unsupported architecture` — trtllm-gen has **no sm120
  build**.
- Found the real route: FlashInfer's sm120 kernel already supports `d_qk=512`
  (`_sparse_mla_sm120.py:32,170`). GLM-5.3 NoPE is 512+0=512. Fix = **zero-pad
  RoPE** onto the packed layout: write `k_pe = zeros[64]`, pad q 512→576, report
  rope dim 64, slice the padded top-k buffer to `index_topk`.
- Validated with a standalone kernel probe *before* touching the model:
  rel err ~2.7%, cosine 0.9996 vs bf16 reference across T=1..64 / H=32,64.
- **Model serves.** `391` ✓, coherent code ✓, needle retrieval exact at
  **113,986 tokens** depths 25/50/90%. Scaled context **16k → 64k → 131,072**
  (KV pool 160,496 tokens, 1.22×, peak 95,546/97,887 MiB).

### Request-logging fix (reasoning models) — the session's main thread
- Deployment team reported `--enable-log-outputs` "accepted but never honoured".
  **Their root cause was wrong**: wiring exists and is reached at runtime
  (`generate/api_router.py:169,174`), and it is **not a fork regression** —
  `upstream/main` and stock 0.21.0 carry the identical guard.
- Real defect: the non-streaming guard builds text from `content`/`tool_calls`

  reasoning-only response logs **nothing** and thinking is never captured.

  plus 2048-char truncation.

## Lessons learned

- **`pkill -f "vllm serve"` kills your own ssh session** — the remote command
  string contains that literal text. Use `"vllm[ ]serve"`. Hit this twice.
- **`git diff upstream/main <branch>` reverts upstream commits.** Our branches
  lag upstream deliberately; diffing against the tip produced a 67-file patch
  that reverted 38 commits onto the build box. Always
  `git diff $(git merge-base upstream/main <b>)..<b>`.
- **A dictConfig that does not name uvicorn's loggers silently deletes its
  output** — startup banner, `Application startup complete`, HTTP access log all
  vanish (measured 2→0) while vLLM's own INFO keeps flowing, so nothing looks
  wrong. Breaks readiness checks that grep for that string.
- **You cannot `rm` a live log file** — measured **199 open descriptors still on
  the unlinked inode**, writes continuing into a nameless file. Same class as
  pointing logrotate at a live file.
- **Model name does not determine code path.** `Qwen3VLDummyInputsBuilder` lives
  in `qwen3_vl.py` but is reused by 8 modules including `qwen3_5.py`, so
  `vllm-code` (Qwen3.8) and `vllm-chat` (Qwen3.6) both load it. I got the scope
  wrong twice — first "no container runs VL" (wrong: matched on names), then
  needed `--limit-mm-per-prompt` to know whether it *fires*.
- **Capture behaviour follows the parser config, not the model.** The logging bug
  triggers on a configured `--reasoning-parser`, not on a reasoning-capable
  model. Deployment team caught this; my runbook had claimed `vllm-chat` was
  losing thinking based on its chat template.
- **`get_supported_head_sizes()` gates backend *selection*** — changing it on a
  base class affects every subclass. The GLM-5.3 patch widens it to `[512,576]`,
  which also makes the sm100 backend eligible for head_size 512.
- **Idempotency needs a post-patch marker, not the anchor.** Our non-streaming
  replacement *ends with* the text it replaces, so the anchor still matches after
  a successful patch — checking the anchor alone would double-apply.
- **File-level collision checks are conservative.** `qwen3-vl-skip-zero-video`
  and the startup branch both touch `qwen3_vl.py` yet compose in both orders
  (different functions). A file hit means "verify", not "conflict".
- **vllm-build has no CUDA toolkit** (no `nvcc`, nothing in `/mnt/packages` but
  the driver). FlashInfer's *sampler* JIT needs it. Workaround:
  `VLLM_USE_FLASHINFER_SAMPLER=0 VLLM_USE_DEEP_GEMM=0
  VLLM_ATTENTION_BACKEND=TRITON_ATTN --enforce-eager`.
- **KV cost per token falls with context length** (~21 KB @16k → ~11 @64k →
  ~9.5 @128k). Extrapolating from 16k made 128k look impossible; it was
  comfortable.
- **vLLM's CUDA-graph memory *estimate* over-charges ~0.6 GiB** vs ~0.3 real.
  `VLLM_MEMORY_PROFILER_ESTIMATE_CUDAGRAPHS=0` + `--kv-cache-memory-bytes`
  unlocked 128k.

## Decisions made

**Choice:** Where documentation lives.
**Picked:** All docs and overlay artifacts on `main`; topic branches code-only.
**Why:** Docs were spread across four branches with none on `main` — consumers
had to know which branch. `main` is never rebased or deleted.
**Alternatives considered:** Per-branch root `OVERLAY.md` (rejected — every
branch would write the same path, colliding on compose); leaving as-is.

**Choice:** How to ship the logging fix across four vLLM versions.
**Picked:** A content-based Python installer, not a `.patch` file.
**Why:** The target files live at three different paths across 0.21.0 / jasl /
upstream, but the code is byte-identical.
**Alternatives considered:** Per-version patch files (3× maintenance).

**Choice:** One log file for prompts + completions, or two.
**Picked:** One (`/var/log/vllm/requests.log`).
**Why:** Two files fill at different rates, so a prompt could be pruned while its
completion survives — an orphaned half is worthless. Verified under 8 concurrent
requests: 32 records, 0 torn lines, 8/8 ids with both halves.
**Alternatives considered:** Split by kind; per-request files (inode explosion,
rotation stops working).

**Choice:** In-container log path.
**Picked:** `/var/log/vllm/requests.log` (vLLM-native convention).
**Why:** User's point — the bind mount provides fleet uniformity, so the
container should follow the app's own convention and stay portable.
**Alternatives considered:** `/var/log/inference/` (rejected — bakes a
fleet-specific path into a portable artifact).

**Choice:** Port SGLang's multi-level request logger?
**Picked:** No. Config-only file sink instead.
**Why:** Upstream #40155 has an active design with a volunteer implementer;
duplicating ~300 LOC in the fork would be throwaway. Our actual need (files) is a
dictConfig change.
**Alternatives considered:** Full port (rejected); revisit if #40155 stalls.

**Choice:** Deploy note for the Qwen3-VL patch?
**Picked:** Yes, after establishing it actually fires on `vllm-code`.
**Why:** I initially declined, believing it a fleet-wide no-op. That was wrong —
see lessons.
**Alternatives considered:** Skip the note (would have been based on a false
premise).

1. **Check live state before touching GPUs** — both cards are shared by
   `vllm-code` (249), `sglang` (250), `vllm-build` (251), `llamacpp` (207):
   ```bash
   ssh root@pve-ai 'pct list | grep -E "vllm|sglang|llamacpp"'
   ssh root@vllm-code 'docker ps; nvidia-smi --query-gpu=index,memory.used --format=csv,noheader'
   ```
2. **Kill a stuck serve** (setproctitle defeats `pkill -f`):
   ```bash
   ssh root@<host> 'for p in /proc/[0-9]*; do e=$(readlink -f "$p/exe" 2>/dev/null); case "$e" in */uv/python/*) kill -9 "${p##*/}";; esac; done'
   ```
3. **Restart models:**
   ```bash
   ssh root@vllm-code '/opt/glm53-exp/serve-glm53-128k.sh'            # GLM-5.3 @128k
   ssh root@vllm-code 'bash /opt/vllm-dsv4/serve-dsv4-k5greedy-128k.sh'  # DeepSeek k5-greedy
   ```
   They contend — only one at a time.
4. **Extract any overlay patch** (never diff against `upstream/main` directly):
   ```bash
   cd /Users/mardel/src/opensource/vllm/vllm-custom
   BASE=$(git merge-base upstream/main <branch>)
   git diff $BASE..<branch> -- vllm/ csrc/ > /tmp/overlay.patch
   ```

   ```bash
   scp overlays/request-logging/apply-reasoning-log-fix.py root@<host>:/tmp/
   ```
